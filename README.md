# PDF Notes — скелет Android-приложения (MVP)

Kotlin + Jetpack Compose, Clean Architecture (UI → Domain → Data), 100% офлайн.

## Как получить APK через GitHub Actions (без Android Studio)

1. Создайте новый пустой репозиторий на github.com (публичный или приватный — не важно).
2. Загрузите в него содержимое этой папки (`PdfNotesApp`) — можно через веб-интерфейс
   GitHub ("Add file → Upload files", перетащить всё содержимое папки) или через git:
   ```
   cd PdfNotesApp
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/НАЗВАНИЕ_РЕПО.git
   git push -u origin main
   ```
3. Откройте вкладку **Actions** в репозитории на GitHub — сборка запустится автоматически
   (займёт 2-4 минуты). Если не запустилась сама — нажмите на workflow "Build debug APK" →
   "Run workflow".
4. Когда сборка завершится зелёной галочкой, откройте её и внизу страницы в разделе
   **Artifacts** скачайте `PdfNotesApp-debug-apk` — это zip с файлом `app-debug.apk` внутри.
5. Перекиньте `app-debug.apk` на телефон и установите (Android спросит разрешение
   "Установить из неизвестных источников" — это нормально для debug-сборки не из Google Play).

Это debug-сборка (не подписана для публикации в Google Play, но полностью рабочая для
установки и тестирования на своём устройстве).

## Как открыть в Android Studio (альтернатива)

1. Установите Android Studio (Koala или новее).
2. `File → Open` → выберите папку `PdfNotesApp`.
3. Дайте Gradle синхронизироваться (подтянет зависимости из google()/mavenCentral()).
4. Запустите на эмуляторе или устройстве с Android 8.0+ (API 26+).

## Что уже работает

- **Список документов** — импорт PDF через системный файловый пикер (Storage Access Framework), список хранится в Room.
- **Просмотр PDF** — постраничный рендеринг через встроенный `android.graphics.pdf.PdfRenderer` (без внешних библиотек).
- **Хайлайты** — выделение области на странице жестом drag, сохраняется в Room с нормализованными координатами (0..1), поэтому не "уезжает" при повороте экрана или другом размере окна.
- **Заметки** — тот же жест, но с диалогом ввода текста вместо цвета.
- Заметки/хайлайты привязаны к конкретной странице и подгружаются реактивно (`Flow`) при пролистывании.

## Архитектура

```
ui/          — Compose экраны + ViewModel (знают только про Domain use case'ы)
domain/      — модели, интерфейсы репозиториев, use case'ы (чистый Kotlin, без Android)
data/        — Room (заметки/документы), обёртка над PdfRenderer, реализации репозиториев
di/          — простой ручной DI-контейнер (AppContainer + ViewModelFactory)
```

Domain ничего не знает о Room или Android SDK — только интерфейсы `DocumentRepository` /
`AnnotationRepository`. Это специально сделано так, чтобы дальше можно было:

- заменить `PdfRendererWrapper` на PdfBox-Android/MuPDF, когда понадобится редактирование PDF,
  не трогая UI и Domain;
- добавить конвертацию в Word/Excel/JPG как новые методы в Data слое;
- добавить облачную синхронизацию или ИИ-конспектирование как ещё одну реализацию
  `AnnotationRepository`/новый репозиторий — Domain и UI не изменятся вообще.

## Что осознанно не реализовано в этом скелете

- **Редактирование PDF** (добавление текста/изображений в сам файл, не только заметки поверх) —
  `PdfRenderer` только для чтения; для этого нужна отдельная библиотека (PdfBox-Android).
- **Конвертация форматов** (PDF → Word/Excel/JPG) — следующий шаг, отдельный `PdfConverter` в Data слое.
- **Инструменты PDF** (merge/split/сжатие/пароль/водяной знак) — то же самое, отдельные адаптеры.
- Иконка приложения (`ic_launcher`) — нужно добавить через Android Studio Asset Studio, иначе
  манифест на неё сошлётся, но сборка debug-варианта это не блокирует благодаря дефолтным ресурсам.
- Тесты — структура с интерфейсами уже располагает к unit-тестам use case'ов через фейковые репозитории,
  но сами тесты не написаны.

## Следующие шаги

редактирование (добавление текста), 3) остальные PDF-инструменты, 4) (опционально) ИИ-конспектирование
